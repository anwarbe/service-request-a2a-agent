2. Architecture & Available Tools

This A2A Server runs on Google Cloud Run in Google Cloud Partner Engineering tenancy, powered by Google Agent Development Kit (ADK 2.0) and Vertex AI (gemini-3.5-flash). Inside the A2A Server is a ServiceNow-style IT & Supply Chain Service Request Agent (a2a_server_agent) that reads and persists trouble tickets to Google Cloud Storage (GCS) (gs://iamtests-315719-oracle-hackathon-tickets/tickets/*.json).

Tool Name Description Parameters
create_trouble_ticket Creates a new IT or Supply Chain trouble ticket and stores tickets/<ticket_id>.json in GCS. Automatically routes HIGH/CRITICAL tickets to L3 Database & Cloud Ops. summary, severity (LOW, MEDIUM, HIGH, CRITICAL), category (DATABASE, SUPPLY_CHAIN, ERP_FUSION, IT_INFRASTRUCTURE), user_email, description
get_ticket_status Retrieves real-time status, assignee, severity, and resolution notes for a ticket ID from GCS. ticket_id (e.g. REQ-20261006123055-A68F)
update_ticket_status Updates an existing ticket's status and records resolution notes in GCS. ticket_id, status (OPEN, IN_PROGRESS, PENDING_CUSTOMER, RESOLVED, CLOSED), resolution_notes
list_trouble_tickets Lists recent trouble tickets stored in GCS, optionally filtered by status. status_filter (e.g. OPEN, RESOLVED), limit (default 10)

3. Step-by-Step Setup in Oracle AI Studio

Step 1: Verify the A2A Agent Card Discovery URL

Verify that the discovery endpoint returns the agent's skills and JSON-RPC endpoint:

curl -s https://service-request-a2a-agent-kavsor5jha-uc.a.run.app/.well-known/agent-card.json | jq .

Step 2: Register the Remote A2A Connection in Oracle AI Studio

  1. Open Oracle AI Studio in your Oracle Fusion / AI World hackathon environment.
  2. Navigate to Agents / Remote Agents (A2A Connections) and click Add Remote A2A Agent.
  3. Enter the connection details:
    • Name: a2a_server_agent
    • Agent Card / Discovery URL: https://service-request-a2a-agent-kavsor5jha-uc.a.run.app/.well-known/agent-card.json
    • A2A Endpoint URL: https://service-request-a2a-agent-kavsor5jha-uc.a.run.app
    • Authentication: Select None (or pass header X-API-KEY: oracle-ai-world-2026).
    • Optional Custom Headers: Add X-Caller-Id: team-<your-team-name> to tag your team's A2A requests.
  4. Save the connection and attach a2a_server_agent to your Oracle AI Studio workflow.

4. Direct JSON-RPC 2.0 Testing (curl & Python)

Option A: curl (A2A v0.3 message/send)

curl -s -X POST "https://service-request-a2a-agent-kavsor5jha-uc.a.run.app/" \
  -H "Content-Type: application/json" \
  -H "A2A-Version: 0.3" \
  -H "X-Caller-Id: oracle-hackathon-team-1" \
  -H "X-Caller-Role: Oracle AI Studio Participant" \
  -H "X-API-KEY: oracle-ai-world-2026" \
  -d '{
    "jsonrpc": "2.0",
    "id": "req-001",
    "method": "message/send",
    "params": {
      "message": {
        "messageId": "msg-001",
        "role": "user",
        "parts": [
          {
            "kind": "text",
            "text": "Create a HIGH severity ticket in category SUPPLY_CHAIN for Order Fulfillment sync delay reported by participant@oracle.com"
          }
        ]
      }
    }
  }' | jq .

Option B: Python Client Using Google ADK RemoteA2aAgent

from google.adk.agents import LlmAgent
from google.adk.agents.remote_a2a_agent import RemoteA2aAgent

remote_a2a_server_agent = RemoteA2aAgent(
    name="a2a_server_agent",
    description="Handles IT and Supply Chain trouble tickets stored in Google Cloud Storage.",
    agent_card="https://service-request-a2a-agent-kavsor5jha-uc.a.run.app/.well-known/agent-card.json",
)

orchestrator = LlmAgent(
    name="oracle_fusion_orchestrator",
    model="gemini-3.5-flash",
    instruction="Delegate any IT or Supply Chain trouble ticket requests to a2a_server_agent.",
    sub_agents=[remote_a2a_server_agent],
)
